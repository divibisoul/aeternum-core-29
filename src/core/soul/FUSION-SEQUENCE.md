# SOUL Fusion Sequence

## Operating directive

N01-N06 remain independent IAs. Soul Mesh remains the shared communication layer. Fusion is capability composition, not ownership transfer and not creation of a parallel Mesh.

## Simultaneous pair stage

Each stage evaluates two connections concurrently at the architectural level. A pair is not considered complete merely because both endpoints exist: capabilities, agents, tools, functions, inputs, outputs, transport, request/response correlation, failure handling and runtime compatibility must be examined together.

## Composition rule

For each simultaneous pair result, cross-capability combinations must be evaluated. A higher-level fusion candidate exists only when the composition exposes a useful capability/function/tool/agent relationship that neither side provides alone. Numerical synergy scores are heuristics; they are not evidence of a doubled capability until a real execution path validates the composition.

## Sequence integrity

The order N01-N06 is preserved unless repository evidence demonstrates a different intended topology. Do not skip a transition merely because another connection appears easier. A completed stage produces a machine-readable handoff containing findings, changes, validation evidence, unresolved dependencies and the next executable action.

## Non-destructive optimization

Prefer existing protocols, registries, runtimes, agents, transports and dependencies. Adapt or compose before adding new infrastructure. Do not create parallel Meshes or duplicate communication protocols. Changes must remain compatible with the global six-nucleus architecture.

## Concurrent work safety

Independent files and scopes may be developed in parallel. The same file or conflicting architectural contract must not be overwritten concurrently. Integration must reconcile concurrent results before declaring the stage complete.
