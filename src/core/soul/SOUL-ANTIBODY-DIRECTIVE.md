# SOUL Antibody Directive

This directive is cumulative with every previous SOUL instruction.

## Operating rule

Every verified defect, omission, incomplete implementation, disconnected component, fragile boundary, dead path, mock presented as production, missing registration, missing exposure, unused capability, integration mismatch or avoidable performance/security weakness is an actionable engineering target.

Detection must transition directly into remediation whenever the current repository and available interfaces provide enough evidence to make a safe change.

DETECT → LOCATE → REPAIR → COMPLETE → INTEGRATE → VALIDATE → RECORD → CONTINUE.

## No passive failure reporting

A finding must not end as a comment when an implementation change is possible. If the exact repair depends on another nucleus, preserve the local improvement, create a precise machine-readable handoff, and continue all independent work rather than blocking the entire stage.

## Six-front awareness

The repository is shared by six simultaneous development conversations. Before modifying a contract, inspect the current branch, recent commits and existing implementation so work from another front is preserved. Never infer that missing conversation context means missing repository work.

## Simultaneous fusion requirement

The three first-level streams remain conceptually concurrent:

N01×N02 || N03×N04 || N05×N06

Their real capabilities, agents, tools, functions, contexts, execution paths and integration evidence must be crossed before higher-level fusion is declared. Do not serialize the discovery merely for convenience.

## Evidence rule

A capability is considered real only when its implementation/registration/exposure/execution path is supported by repository evidence. A synergy score is a prioritization signal, not proof of an emergent capability. Emergent capabilities require a concrete composition contract and a validation path.

## Progress rule

Never restart completed work merely to satisfy this directive. Extend it. When a defect is found in an existing upgrade, repair the smallest compatible surface that restores the intended architecture, then continue from the resulting state.
